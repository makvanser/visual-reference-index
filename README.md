# Visual Reference Index

React/Vite-каталог для просмотра и анализа визуальных референсов сайтов. Он работает локально и публикуется как интерактивная статическая страница на GitHub Pages.

**Публичная версия:** https://makvanser.github.io/visual-reference-index/

У каждой карточки есть кнопка `Скачать .md`, которая экспортирует полный анализ выбранного референса в отдельный Markdown-файл.

## Запуск

```powershell
npm install
npm run dev
```

Перед `dev` автоматически выполняется `npm run scan`, после чего каталог открывается по адресу `http://localhost:5173`.

Проверка production-сборки:

```powershell
npm run build
npm run preview
```

Полная локальная проверка перед публикацией:

```powershell
npm test
npm run scan
npm run validate
npm run build
```

## Как добавить новые скриншоты

1. Положите исходные JPG, PNG, WebP или AVIF в `screens/`.
2. Запустите `npm run scan`.
3. Откройте `data/pending-analysis.json`. Там появятся только новые файлы, которым нужен визуальный анализ.
4. Проанализируйте новые изображения вручную или с AI и добавьте полные записи в `data/references.json`. При необходимости дополните `data/families.json` или назначьте существующую семью.
5. Запустите `npm run scan` повторно, затем `npm run validate`.
6. Обновите открытую страницу каталога.

`npm run scan` синхронизирует изображения из `screens/` в `public/screens/` и составляет список необработанных файлов. Скрипт намеренно не имитирует vision-анализ и не создаёт выдуманные метаданные.

## Основные файлы

- `screens/` - исходные изображения.
- `public/screens/` - копии, которые обслуживает Vite.
- `public/materials/<reference-id>/` - дополнительные локальные материалы из проверенных источников.
- `data/references.json` - полный анализ каждого референса.
- `data/families.json` - описания и палитры семейств.
- `data/pending-analysis.json` - очередь новых файлов после scan.
- `src/App.jsx` - фильтрация, поиск, карточки, URL state и модальное окно.
- `src/styles.css` - нейтральная editorial-система и responsive layout.
- `scripts/scan-screens.mjs` - индексирование и синхронизация изображений.
- `scripts/validate-data.mjs` - проверка схемы, файлов, цветов и family counts.

Исходные изображения не переименовываются и не изменяются.

Дополнительные источники хранятся в необязательном поле `source_materials` конкретного референса. Интерфейс и Markdown-экспорт автоматически показывают источник, авторов, награды, технологии, выделенные элементы и локальную галерею изображений или motion-превью, если это поле присутствует.

## GitHub Pages

Публикация выполняется автоматически после push в `main` через `.github/workflows/deploy-pages.yml`. Workflow устанавливает зависимости, запускает тесты и валидацию, задаёт `VITE_BASE_PATH=/visual-reference-index/`, синхронизирует `public/screens/` через lifecycle-скрипт `prebuild`, собирает приложение и отправляет `dist/` в GitHub Pages.

Ручной запуск доступен на вкладке **Actions → Deploy catalogue to GitHub Pages → Run workflow**.
